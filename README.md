# Demo studio

A prifly extension that turns a brief into a script and a storyboard for a narrated product demo video. Claude makes the video (`demo_create`) and writes the script through the `demo_*` tools; there is no panel: videos are made and reviewed in a prifly session, where the viewer (a session view, `demo_open`) sits beside the chat and the reader asks for changes in words.

Brief, script and dry run are tools. The dry run (the `demo_dry_run` tool) builds one page from the product's own mockup harness at its checkout's HEAD commit (or at the commit a scene's `source.ref` names: a branch or commit of the product's repository, fetched from origin when the checkout lacks it), in a throwaway `git worktree` under the video's `build/` folder with the checkout's node_modules linked in. The page is cached in `_harness-cache/`. The dry run then performs every scene's steps in its own chrome-headless-shell (1920×1080, one at a time) and saves one still per scene in `stills/`. On a Windows host the git and build commands run inside WSL through `wsl.exe` (settings: ODI checkout, prifly checkout, WSL distribution). There the worktree sits on WSL's own disk, `~/.cache/prifly-demo-video/build/`, and only the composed page comes back to the host's `_harness-cache/`. The browser is the Windows build of chrome-headless-shell.

Render (the `demo_render` tool) voices every scene into `audio/<lang>/<scene>.mp3` (Edge draft voices, or ElevenLabs when the session passes `voice: "final"`; cached by text and voice; the version records which), records each scene with a drawn cursor into `takes/<scene>/` (frames with their times, and `events.json`), and makes `out/<lang>.mp4` at 1920×1080: a steady 30 fps rebuilt from the frames, a zoom toward each click, burned-in subtitles, the scenes joined and the narration mixed in. `h264_nvenc` when it works here, else `libx264`. `redo: "noted"` records and re-renders only the scenes with notes. Voice and render run on the host's side with the host's ffmpeg (on PATH, where winget puts it, or the `ffmpegPath` setting); nothing goes into WSL. The viewer plays the result through prifly's `panel-media` route; without it the tool answers with the file's path. Export comes in a later version.

## Layout

- `prifly-extension.json`: manifest (session view, settings).
- `index.ts`: `activate` (registers the tools) and `panel`, which answers the session view's `api/state`.
- `prompt.md`: house rules added to Claude's system prompt.
- `src/`: store, scene schema, timing and house rules, tools, the session view's state (`timeline-state.ts`, `panel-api.ts`); `browser.ts`, `exec.ts`, `dry-run.ts`, `dry-run-service.ts` and `sources/` (harness build) for the dry run; `voice.ts` and `voice-reference.ts`, `take.ts`, `render.ts` (the ffmpeg arguments, a pure function), `render-run.ts`, `render-service.ts` and `ffmpeg.ts` for the render.
- `session-view/`: the viewer page (plain ES modules, no build).
- `test/`: `bun test`, over a fake prifly api.

## Voice

- `demo_render` takes `voice: "draft" | "final"` (default draft: Edge voices; final: ElevenLabs, with the key, voice id and model from the settings). Each version's `version.json` records `voice` (mode, engine, voice per language, model) and the viewer's header shows it; a version made before that shows "Voice: unknown".
- `voice: "mine-elevenlabs"` (the no-GPU way to the reader's own voice; the local one is `"mine"`): `src/voice-mine-elevenlabs.ts` makes an ElevenLabs Instant Voice Clone (`POST /v1/voices/add`) from `<videos>/_voice/reference.wav` once, keeping its voice id and the file's sha256 in `<videos>/_voice/clone.json` (a changed reference makes a new clone and deletes the old one), then per scene Edge reads the narration (the language's configured Edge voice) and ElevenLabs' voice changer (`POST /v1/voice-changer/{voice_id}`, model `eleven_multilingual_sts_v2`) turns that MP3 into the clone's voice. It spends ElevenLabs credits per minute, uses the `elevenLabsKey` secret, and needs `demo_voice_reference` first. `demo_voice_clone_delete` deletes the clone and forgets it. The version records mode `mine-elevenlabs`, engine `elevenlabs-sts`, the clone id, the model and the Edge source voice; the header says "Voice: Mine (ElevenLabs)".
- `voice: "mine"` (the reader's own voice, converted on the local NVIDIA GPU; nothing leaves the machine but Edge's reading): `src/voice-mine-local.ts` has Edge read each scene in en-GB (the configured English voice when it is en-GB, else Sonia), then `python/convert.py` (Seed-VC pinned to a commit, fetched on first run into `<videos>/_seed-vc/`) converts it to `reference.wav` with `--diffusion-steps 100 --length-adjust 1.0 --inference-cfg-rate 0.7 --fp16 True`; variant B (default: `--f0-condition True --auto-f0-adjust True`, 44.1 kHz) or A (both False, 22 kHz) by the "My voice: Seed-VC variant" setting. One Python process converts every scene of a render (JSON lines over stdin/stdout; the model loads once). The Python is the venv prifly builds from `pyproject.toml` and `uv.lock` (CUDA 12.4 torch on Windows); a missing venv, GPU or `reference.wav` is one line and the render stops, with no fallback to Edge. The narration is cached by text and voice, the voice including the hash of `reference.wav` and the variant; `version.json` records engine, variant and reference hash. `bun scripts/render-mine.ts --setup` and then `bun scripts/render-mine.ts` are the manual end-to-end check from WSL (see the header of that file).
- `demo_voice_samples` speaks a short line in three voices into `<videos>/_voice-samples/` and answers with the three absolute paths and which voice and model each is.
- `demo_voice_reference` builds `<videos>/_voice/reference.wav` (about 20 s, mono, 16-bit, 48 kHz) from the reader's own recordings: the setting "Your voice reference folder", else, with "Use my dictation recordings" on, prifly's dictation recordings. The extension contract names no data folder, so `src/data-dir.ts` derives it the way prifly does (`$XDG_DATA_HOME/prifly` or `~/.local/share/prifly`, macOS `~/Library/Application Support/prifly`, Windows `%LOCALAPPDATA%\prifly\host`) plus `dictation-recordings/YYYY-MM-DD/HHMMSS-<dict>-<piece>.wav` with its `.json` (the `text`). A piece's `.full.wav` is preferred, else its `.wav`. ffmpeg's `volumedetect` and `silencedetect` rank the pieces of 2 to 12 s by clarity (quiet, hot, clipping, pauses; see `src/voice-reference.ts`); pieces at other rates are resampled to 48 kHz. `voice: "mine"` converts the narration to it.

## Develop

    bun install --frozen-lockfile
    bun test
    bun node_modules/typescript/bin/tsc --noEmit   # or: bun run typecheck where node is recent
    bun node_modules/@biomejs/biome/bin/biome check .

Videos live in the extension's data folder, one folder per video (`brief.json`, `scenes.json`, `stills/`, `audio/`, `takes/`, `out/`). Each render also becomes a version, `out/v<N>/` (the MP4s, a waveform picture per scene, a `scenes.json` snapshot and `changes.json`; `out/latest.json` names the newest, the last ten stay), which the Demo studio session view (`demo_open`, in the session's App tab) shows as a timeline.
